---
title: "Subscriptions"
description: "Scene, camera, DOM, webview, and input events, and the body each delivers."
---

Subscriptions push events to your driver. They travel through the same envelope as commands — a subscription **is** a command whose response returns a `subscriptionId`:

```ts
type ProtocolSubscription<T, REQ> = ProtocolCommand<
    T,
    REQ,
    { subscriptionId: string }
>;
```

## Subscribing

Issue the `subscription:*` command in `activate`; the response carries the id you use to unsubscribe:

```ts
const res = await issueCommand({
    type: "subscription:camera:moved-debounced",
    driverId,
    requestId: nextRequestId(),
});
const subscriptionId = res.res.value.subscriptionId;
```

From then on, matching events arrive in `onEvent`:

```ts
type ProtocolSubscriptionEvent<T, BODY> = {
    type: T;
    subscriptionId: string;
} & (BODY extends undefined ? {} : { body: BODY });
```

Dispatch on `event.type`, read `event.body`, and unsubscribe with [`command:subscription:remove`](/protocol/commands#subscription-management).

Each subscription topic below lists its request (the `subscription:*` `req`) and the `body` of the event it delivers.

## Typing a subscription

Same `Extract` pattern as commands — `SubscriptionCommand` for the subscribe request, `DriverSubscriptionEvent` for the event it delivers:

```ts
import type {
    SubscriptionCommand,
    DriverSubscriptionEvent,
} from "@drawdy/driver-protocol";

type PointerReq = Extract<
    SubscriptionCommand,
    { type: "subscription:scene:pointer" }
>;
type PointerEvent = Extract<
    DriverSubscriptionEvent,
    { type: "subscription:scene:pointer" }
>;
```

`PointerReq` carries `req` (here `{ elementIds? }`); `PointerEvent` carries `body`.

## Scene events

```ts
"subscription:scene:elements-added"
req:  { properties: SubscribeableKey[] }
body: {
    drawdyElements: readonly SubscribedDrawdyElement[];
    properties: SubscribeableKey[];
}

"subscription:scene:elements-removed"
req:  { properties: SubscribeableKey[] }
body: {
    drawdyElements: readonly SubscribedDrawdyElement[];
    properties: SubscribeableKey[];
}

"subscription:scene:elements-updated"
req:  { properties: SubscribeableKey[] }
body: {
    drawdyElements: readonly SubscribedDrawdyElement[];
    properties: SubscribeableKey[];
}

"subscription:scene:elements-replaced"
req:  { properties: SubscribeableKey[] }
body: {
    drawdyElements: readonly SubscribedDrawdyElement[];
    replaced: readonly SubscribedDrawdyElement[];
    properties: SubscribeableKey[];
}

"subscription:scene:activity"
req:  { rect: { x: number; y: number; width: number; height: number } }
body: {
    drawdyElementIds: string[];
    rect: { x: number; y: number; width: number; height: number };
}

"subscription:scene:pointer"
req:  { elementIds?: string[] }
body:
    | {
          type: "up" | "down";
          drawdyElementIds: string[];
          pressure: number;
          cursor: {
              domSpace: { x: number; y: number };
              canvasSpace: { x: number; y: number };
          };
      }
    | {
          type: "enter" | "out";
          drawdyElementIds: string[];
          cursor: {
              domSpace: { x: number; y: number };
              canvasSpace: { x: number; y: number };
          };
      }
    | { type: "cancel" }

"subscription:scene:click"
req:  { elementIds?: string[] }
body: {
    drawdyElementIds: string[];
    cursor: {
        domSpace: { x: number; y: number };
        canvasSpace: { x: number; y: number };
    };
}

"subscription:scene:text-edit"
body:
    | {
          type: "update";
          rect: { x: number; y: number; width: number; height: number };
          font: number;
          lineHeight: number;
          text: string;
      }
    | { type: "commit" | "cancel" }

"subscription:scene:drawdy-element-selection"
body: { drawdyElementIds: string[] }
```

The `properties` you pass when subscribing to element events select which fields populate each returned [`SubscribedDrawdyElement`](/protocol/data-types#element-properties). `elements-replaced` reports both the new elements (`drawdyElements`) and the ones they replaced (`replaced`). `scene:activity` fires whenever there is activity inside the rect you registered.

`scene:pointer` reports pointer activity over scene elements — `type` says which: `down`/`up` are presses (they carry `pressure`), and `enter`/`out` fire once as the pointer moves onto or off an element (hover — no `pressure`). Both report every element under the cursor (`drawdyElementIds`) and the position in both `domSpace` (screen/client pixels) and `canvasSpace` (world coordinates). `cancel` fires when the gesture is aborted and carries nothing. Pass `req.elementIds` to hear only about `down`/`up`/`enter`/`out` that land on those elements (the body is narrowed to the matching ids); omit it to hear about any element. `enter`/`out` are suppressed while drawing. Pointer events over empty canvas don't fire, but `cancel` always reaches every subscriber.

`scene:click` fires on a completed click — a pointer press and release that land on the same scene element(s) — reporting the elements clicked (`drawdyElementIds`) and the cursor position. Like `scene:pointer`, pass `req.elementIds` to hear only about clicks on those elements (the body is narrowed to the matching ids); omit it to hear about any element. It's the scene-level counterpart to [`subscription:dom:element-clicked`](#dom-events) — use it for clicks on canvas elements (including component/widget elements), which live in the scene rather than the host DOM.

`scene:drawdy-element-selection` fires whenever the canvas selection changes, delivering the full set of currently selected ids (`drawdyElementIds` is empty when the selection is cleared) — not a delta. Read the current selection at any time with [`command:scene:get-current-selected-drawdy-elements`](/protocol/commands#scene-elements).

## Camera events

```ts
"subscription:camera:moved-rapid";
body: {
    x: number;
    y: number;
    zoom: number;
}

("subscription:camera:moved-debounced");
body: {
    x: number;
    y: number;
    zoom: number;
}
```

`moved-rapid` fires continuously during movement; `moved-debounced` fires once movement settles.

## DOM events

```ts
"subscription:dom:element-clicked";
req: {
    domElementId: string;
}
body: {
    domElementId: string;
    clientX: number;
    clientY: number;
}

("subscription:dom:pointer");
req: {
    domElementId: string;
}
body:
    | {
          type: "enter" | "out";
          domElementId: string;
          clientX: number;
          clientY: number;
      }
    | { type: "cancel"; domElementId: string }

("subscription:dom:theme-changed");
body: {
    styling: ModuleStyling;
}

("subscription:dom:fullscreen-changed");
body: {
    fullscreen: boolean;
}

("subscription:dom:screen-resized");
body: {
    width: number;
    height: number;
}

("subscription:dom:drag");
req: {
    domElementId: string;
}
body: {
    type: "dragStart" | "dragging" | "dragEnd";
    domElementId: string;
    position: {
        canvasSpace: {
            x: number;
            y: number;
        }
        domSpace: {
            x: number;
            y: number;
        }
    }
}
```

`element-clicked` fires when the named element is clicked — scoped to `req.domElementId`, reporting the pointer position in client pixels.

`dom:pointer` is the DOM counterpart of [`scene:pointer`](#scene-events), scoped to `req.domElementId`: `enter`/`out` fire once as the pointer moves onto or off the element (each carries the pointer position in client pixels), and `cancel` fires when the pointer interaction is aborted. `enter`/`out` fire on element changes, not on every move within the element.

`theme-changed` delivers the updated [`ModuleStyling`](/protocol/data-types#modulestyling) whenever the user switches theme.

`drag` is **scoped to the element you name in `req.domElementId`**: it fires only for gestures that **start on that element** (the drag is tracked document-wide and its start element latched for the whole gesture, so events keep coming even after the pointer leaves — e.g. while you drag a floating element around). One `dragStart` on pointer-down, a `dragging` per move while held, one `dragEnd` on pointer-up. It is synthesized from raw pointer events rather than the browser's native drag, so it fires reliably. Each event's `domElementId` echoes the element the gesture started on. `position` carries both coordinate spaces: `domSpace` (screen/client pixels, for `command:dom:move-floating-element`) and `canvasSpace` (world coordinates, ready to use). Grab a floating element by giving its `create-floating-element` `schema` `pointerEvents: "auto"` so it receives the pointer-down.

## Webview events

```ts
"subscription:webview:message";
req: {
    webviewDomId: string;
}
body: {
    webviewDomId: string;
    message: unknown;
}
```

## Input events

```ts
"subscription:context-menu:clicked";
req: {
    menuId: string;
}
body: {
    menuId: string;
}

("subscription:keyboard:control-keys");
body: {
    key: ControlKey;
    shift: boolean;
    ctrl: boolean;
    meta: boolean;
    alt: boolean;
}
```

```ts
type ControlKey =
    | "tab"
    | "enter"
    | "shift"
    | "escape"
    | "space"
    | "backspace"
    | "delete"
    | "arrow-up"
    | "arrow-down"
    | "arrow-left"
    | "arrow-right";
```
